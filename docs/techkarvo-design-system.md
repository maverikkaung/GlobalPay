# TechKarvo ဒီဇိုင်းစနစ်နှင့် လမ်းညွှန်ပုံ

**Milestone 4.0 · ကိုယ်ပိုင်ဒီဇိုင်း အဆိုပြုချက်**

ဤစံကို အဆင့်လိုက် ထည့်သွင်းမယ်။ လက်ရှိ `theme.css` မှ `--tk-*` အရောင်နှင့် `ThemeProvider` ၏ local preference ကို အခြေခံမယ်။ အောက်ပါ အရောင်၊ component နှင့် လမ်းကြောင်းများကို ဒီဇိုင်းရည်မှန်းချက်အဖြစ် သတ်မှတ်ထားတယ်။ လက်ရှိ အကျုံးဝင်မှုကို UX စစ်ဆေးချက်တွင် ကြည့်နိုင်တယ်။ [လက်ရှိ theme](../src/theme.css) · [UX စစ်ဆေးချက်](techkarvo-ux-audit.md)

## ၂။ စာလုံးနှင့် အကွာအဝေး

လက်ရှိ Arial နဲ့ ချောမွေ့စွာ အစားထိုးနိုင်မည့် `system-ui` ကို Latin အခြေခံအဖြစ် သုံးမယ်။ မြန်မာစာအတွက် `Noto Sans Myanmar`, `Myanmar Text`, sans-serif ကို fallback အဖြစ် အဆိုပြုတယ်။ စာမျက်နှာအတွင်း font ကို မတူအောင် ရောမသုံးရ။ လိုင်စင်နှင့် load လုပ်ပုံ အတည်ပြုမချင်း အဝေးမှ font တောင်းခြင်း မထည့်ရ။ Font ပျက်လျှင် စာရွေ့မသွားအောင် fallback စစ်မယ်။

| အဆင့် | အရွယ်နှင့် line-height အဆိုပြုချက် | အသုံးပြုမှု |
| --- | --- | --- |
| ပင်မခေါင်းစဉ် | 28/40 mobile၊ 36/48 desktop၊ 650–700 | စာမျက်နှာနာမည်တစ်ခု |
| ကဏ္ဍခေါင်းစဉ် | 22/32၊ 650 | အလုပ်ခန်း၊ ဖောင်နှင့် ကတ်စာရင်းကဏ္ဍ |
| Card ခေါင်းစဉ် | 18/28၊ 600 | အလုပ်၊ စာတွဲ၊ portfolio၊ plan |
| စာကိုယ်/ဖောင် | 16/26၊ 400 | အကြောင်းအရာ၊ chat၊ input |
| Label/metadata | 14/22၊ label 600 | ရက်စွဲ၊ status အမည်၊ အခကြေးငွေ ရှင်းစာ |

စာအရွယ်တွေကို `rem` ဖြင့် အသုံးပြုပြီး မြန်မာစာတွင် အပေါ်အောက်အမှတ်အသား မဖြတ်စေရန် line-height ကို လိုအပ်သလို တိုးမယ်။ စာကိုယ်ကို desktop မှာ စာလုံး 65–75 ခန့် ဖတ်နိုင်သောအကျယ်ထားမယ်။ အကြောင်းအရာနဲ့ ငွေကြေးကိန်းကို တစ်လိုင်းတည်းလုပ်ပြီး ဖျောက်မထားရ။

- Spacing ကို 4၊ 8၊ 12၊ 16၊ 24၊ 32၊ 48၊ 64px ထဲက သုံးမယ်။ Label နှင့် input 8px၊ form rows 16px၊ sections 24–32px၊ page sections 32–48px။
- Control radius 8px၊ card 12px၊ panel/sheet 16px။ Badge တစ်မျိုးတည်းအတွက် အပြည့်ဝိုင်း သုံးနိုင်မယ်။
- Card နယ်နိမိတ်အတွက် border နဲ့ လေဟာနယ်ကို ဦးစားပေးမယ်။ Popup/modal သီးခြားထင်ရှားဖို့ အရိပ်သုံးမယ်။ Layer အစဉ်မှာ content → sticky → popup → dialog → status announcement ဖြစ်မယ်။

အဆိုပြုအရောင်တန်ဖိုးများကို WCAG contrast နည်းဖြင့် တွက်ရာ လက်တွေ့သုံးမည့် ပင်မခလုတ်စာသားနှင့် နောက်ခံမှာ အလင်း 6.56:1၊ အမှောင် 8.38:1 ဖြစ်တယ်။ နောက်ခံသုံးမျိုးပေါ် status/primary စာသားအတွက် အနည်းဆုံး 5.88:1 နှင့် 7.21:1၊ control border အတွက် အနည်းဆုံး 3.92:1 နှင့် 4.15:1 ရတယ်။ Hover/pressed/disabled၊ တကယ့်ပုံအပေါ် စာသားနှင့် overlay ကို component အကောင်အထည်ဖော်ချိန် ထပ်စစ်မယ်။ [W3C WCAG 2.2](https://www.w3.org/TR/WCAG22/)

လက်ရှိ dark default နှင့် သိမ်းထားသော preference ကို ထိန်းထားမယ်။ နောင် System preference ကို သီးခြားရွေးချယ်နိုင်မယ်။ Theme မည်သည့်အမျိုးအစားဖြစ်စေ `color-scheme`၊ form control၊ ဘဏ္ဍာရေးစမ်းသပ်အမှတ်အသား၊ badge နှင့် focus ရောင်ကို တူညီစနစ်ဖြင့် ထည့်မယ်။ Status ကို icon နှင့် စာသားပေါင်းပြီး ပြမယ်။

| Status၊ timeline၊ toast | အကြောင်းအရာနှင့် အချိန်၊ သက်ဆိုင်ရာ လူ/စနစ်၊ သီးခြား job၊ contract၊ delivery၊ payment label | Toast ကို အရေးကြီးဆုံးအတည်ပြုချက်အတွက် တစ်ခုတည်းသောနေရာ မသုံးရ။ အသစ်အခြေအနေကို စာသားဖြင့် သိနိုင်ပြီး အချိန်ဇုန် မှန်ရမယ်။ |
| Menu၊ sheet၊ dialog | စာသားပါ trigger၊ `aria-expanded` လိုမှသုံး၊ confirmation တွင် အကြောင်းနှင့် သက်ရောက်မှု | Modal မှာ focus အတွင်းပဲ ရှိပြီး Escape/Cancel၊ trigger သို့ ပြန်ရမယ်။ ဖျက်ခြင်း၊ ဖုံးအုပ်ခြင်း၊ ပြီးဆုံးအမှတ်သတ်မှတ်ခြင်းတို့၏ အကျိုးသက်ရောက်မှုကို အတည်မပြုမီ ပြမယ်။ |
| Loading၊ empty၊ error | ပုံစံမရွေ့သော placeholder သို့မဟုတ် loading စာသား၊ empty အကြောင်းနှင့် နောက်ဆက်လုပ်ရန် | မတွေ့ခြင်း၊ ခွင့်မရှိခြင်း၊ ဆက်သွယ်မှုပြတ်ခြင်းနှင့် read-only ကို သီးခြားပြမယ်။ စာရင်းပြန်တင်လျှင် focus ပျောက်မသွားရ။ |

ထိတွေ့လုပ်ဆောင်ချက်အတွက် ပုံမှန် target အနည်းဆုံး 44×44 CSS px သတ်မှတ်မယ်။ Tab အစဉ်က စာဖတ်အစဉ်နှင့် ကိုက်ရမယ်။ Header၊ sheet နှင့် composer က focus ခံရသူကို ဖုံးမထားရ။ UI သုံးနိုင်စွမ်းအတွက် reduced-motion ရွေးထားသောအခါ အလှဆင်လှုပ်ရှားမှုများကို ရပ်ပြီး အခြေအနေပြောင်းလဲမှုကို စာသားနဲ့ ပြမယ်။ [W3C Reflow](https://www.w3.org/WAI/WCAG22/Understanding/reflow)

## ၆။ တိုးချဲ့သုံးမည့် စံ

- ပထမ UX အဆင့်တွင် အလုပ်စာရင်း၊ detail နှင့် proposal အတွက် လိုသလောက် token နှင့် reusable state ပုံစံကို စမ်းမယ်။ ရှိပြီးသား theme၊ route နှင့် ပင်မ UI controls ကို ဆက်သုံးမယ်။
- အစိတ်အပိုင်းတစ်ခုချင်းစီအတွက် အလင်း/အမှောင်၊ `en`/`my` စာလုံးရှည်၊ keyboard၊ 320၊ 390၊ 768၊ 1280px နှင့် 200% zoom ကို ဖမ်းယူစစ်မယ်။ ဖတ်ရန်စာသား၊ state နှင့် link ကို အတည်ပြုပြီးမှ ရုပ်ပုံအလှဆင်မှု ထည့်မယ်။
- ဘာသာပြန်စာကို စာပိုင်းတစ်ပိုင်းစီ ချိတ်ဆက်တည်ဆောက်ခြင်းမှ ရှောင်ပြီး locale catalog၊ ပုံမှန် unit နှင့် အချိန်ဇုန်ကို နောက်တိုးချဲ့မှုအတွက် အသုံးပြုမယ်။ မြန်မာ keyboard စာရိုက်နေစဉ် Enter က စကားဝိုင်းထဲ အမှားဖြင့် မပို့ရ။ [ထုတ်ကုန်လိုအပ်ချက်](techkarvo-product-requirements.md) · [အကောင်အထည်ဖော်အစီအစဉ်](techkarvo-implementation-roadmap.md)
