# TechKarvo ထုတ်ကုန်လိုအပ်ချက်စာတမ်း

**Milestone 4.0 · ဒီဇိုင်းအဆိုပြုချက် · အခြေခံ commit `fa25e2fb415d64cbc5060fffd5e52afc17090a98`**

TechKarvo မှာ Client က အလုပ်လိုအပ်ချက်တင်ပြီး သင့်တော်သူကို ရွေးနိုင်ရမယ်။ Freelancer က အလုပ်ရှာတာကနေ ပေးပို့ပြီးသည့်အလုပ်၊ ပေးချေမှုအခြေအနေနဲ့ သုံးသပ်ချက်ကို မူလအလုပ်နဲ့အတူ ပြန်ရှာနိုင်ရမယ်။ ပညာရှင်ပရိုဖိုင်၊ ကွန်ရက်နဲ့ ဆက်သွယ်ရေးက အဲဒီအလုပ်စဉ်ကို အထောက်အကူပြုရမယ်။ အခြားပလက်ဖောင်းတွေကို လုပ်ဆောင်နိုင်စွမ်းအတွက်သာ ရည်ညွှန်းပြီး TechKarvo ရဲ့ ကိုယ်ပိုင်လမ်းကြောင်း၊ စာသားနဲ့ ရုပ်သွင်ကို သုံးမယ်။ လက်ရှိအခြေအနေနဲ့ အထောက်အထားကို UX စစ်ဆေးချက်မှာ မှတ်တမ်းတင်ထားတယ်။ [UX စစ်ဆေးချက်](techkarvo-ux-audit.md)

| သီးခြားအတည်ပြုချက် | လိုင်စင်ရဝန်ဆောင်မှုပေးသူမှ ကာကွယ်ထားသော စာချုပ်ပေးချေမှု | ဒေသ၊ ငွေကြေး၊ provider နှင့် တာဝန်ခံအဖွဲ့ အတည်ပြုပြီးမှ စမ်းသပ်စနစ်အတွက် ပုံစံချမှတ်မယ်။ Milestone 4.0 မှာ စာတမ်းနယ်ပယ်အတွင်းသာ ဖြစ်တယ်။ |

အောင်မြင်မှုကို detail → proposal အောင်မြင်ပေးပို့မှု၊ proposal → ပထမ အပြန်အလှန်စာ၊ proposal → အပ်နှံမှု၊ အပ်နှံမှု → လက်ခံပြီးပေးပို့မှုနဲ့ ပြီးဆုံးစာချုပ် → review အချိုးတို့နဲ့ တိုင်းမယ်။ ပထမစာနှင့် ပထမပေးပို့မှုအထိ ကြာချိန်ကို median/p90 သီးခြားကြည့်မယ်။ ပထမ UX အဆင့်မတိုင်မီ သက်ဆိုင်ရာစက်အမျိုးအစားနှင့် role အလိုက် baseline တိုင်းပြီး တိုးတက်မှုရည်မှန်းချက်ကို ထိုအချက်အလက်ပေါ်မှာ သတ်မှတ်မယ်။ Event တွေမှာ စာ၊ cover letter၊ အီးမေးလ်၊ ဖိုင်အမည်၊ ငွေပေးချေမှုအချက်အလက် မစုဆောင်းရ။ လုပ်ဆောင်မှုတစ်ခုကို server success အဖြစ် တစ်ကြိမ်သာ ရေတွက်ရမယ်။

## ၂။ သုံးစွဲသူနှင့် လုပ်ပိုင်ခွင့်

| သုံးစွဲသူ | လုပ်ငန်းတာဝန် | ဒေတာနှင့် စည်းမျဉ်း |
| --- | --- | --- |
| Client | အလုပ်ကြော်ငြာ၊ ကိုယ့်အလုပ်လျှောက်ထားသူများကြည့်၊ စကားပြော၊ လက်ခံ/ငြင်း၊ လုပ်ငန်းတိုးတက်မှုစစ်၊ ပေးပို့မှုကို လက်ခံ/ပြင်ဆင်ခိုင်း၊ review ရေး | ပိုင်ဆိုင်သည့်အလုပ်နှင့် စာချုပ်သာ ပြောင်းနိုင်ရမယ်။ အပ်နှံမှု၊ စာချုပ်ဖန်တီးမှုနှင့် သက်ဆိုင်ရာ notification ကို ဆာဗာအဖြစ်အပျက်နဲ့ ချိတ်ရမယ်။ |
| Freelancer | အလုပ်ရှာ၊ လျှောက်လွှာရေး/တင်/ခွင့်ရှိချိန် ပြန်ရုပ်သိမ်း၊ Client နဲ့ စကားပြော၊ အလုပ်ဗားရှင်းပေးပို့၊ ကိုယ့်ပေးချေမှုအခြေအနေကြည့်၊ review ရေး | ကိုယ့်လျှောက်လွှာနှင့် စာချုပ်သာ မြင်ရမယ်။ ပေးပို့မှုကို သက်ဆိုင်ရာပန်းတိုင်နဲ့ ချိတ်ရမယ်။ ကိုယ်ပိုင်ရရှိငွေအခြေအနေကို provider က အတည်ပြုပြီးမှ ပြောင်းမယ်။ |
| Admin | အစီအစဉ်နှင့် platform သတ်မှတ်ချက်၊ moderation၊ အရေးပေါ်ရပ်ဆိုင်းမှု၊ audit နဲ့ အထူးတိုင်ကြားမှု | လက်ရှိ `platform_admins` အတည်ပြုမှုကို ထိန်းမယ်။ နောင် ခွင့်အမျိုးအစားခွဲပြီး ဆုံးဖြတ်ချက်အကြောင်းရင်း၊ actor၊ အချိန်၊ ရင်းမြစ်ကို မှတ်မယ်။ စာတွဲအားလုံး ဖတ်ခွင့် အလိုအလျောက်မပေးရ။ |
| Support | တာဝန်ချထားသည့် အမှုတွဲကို စစ်၊ အသုံးပြုသူထံ ပြန်ကြား၊ တိုးမြှင့်လွှဲပြောင်း၊ အခြေအနေ အသိပေး | သီးခြားဝန်ထမ်းခွင့် အဆိုပြုချက်ဖြစ်တယ်။ လက်ရှိ `/support` မှာ အဖွဲ့ဝင်က ကိုယ့်အမှုတွဲဖွင့်/ဖတ်ပြီး Admin က queue စီမံတယ်။ Support ခွင့်က ငွေပေးချေမှု၊ sandbox configuration၊ plan တည်းဖြတ်မှု သို့မဟုတ် တာဝန်မရှိသည့် စာတွဲကို မပေးရ။ |
| အများသုံးဧည့်သည် | ပင်မစာမျက်နှာ၊ ဖွင့်ထားသောအလုပ်ကြော်ငြာနှင့် demo ကြည့် | လျှောက်လွှာ၊ အဖွဲ့ဝင်ပရိုဖိုင်စာမျက်နှာ၊ စာနှင့် စာချုပ်အတွက် လက်ရှိ authorization ကို ဆက်သုံးမယ်။ Profile လမ်းကြောင်း ဖွင့်ပေးခြင်းကို သီးခြား privacy ဆုံးဖြတ်ချက်အဖြစ် သတ်မှတ်မယ်။ |

Role ပြောင်းလဲမှုနဲ့ Admin/Support ခွင့်ပေးခြင်းကို ဝန်ထမ်း onboarding အဖြစ် သီးခြားစီမံရမယ်။ Browser ရဲ့ menu သို့မဟုတ် route guard တစ်ခုတည်းကို ခွင့်ပြုချက်အဖြစ် အသုံးမပြုရ။ အောက်ခံ [အကောင့်လမ်းကြောင်း](../src/AuthContext.jsx)၊ [လုပ်ပိုင်ခွင့်နှင့် ကူညီရေး schema](../supabase/migrations/202611150012_admin_support_configuration.sql) ကို ဆက်လက်စစ်ရမယ်။

## ၄။ စကားပြောခန်းနှင့် အလုပ်ခန်း

- **ဆက်စပ်မှု**။ မူလလျှောက်လွှာကို database က ချိတ်ထားသည့် စာတွဲကို အပ်နှံပြီးနောက် ဆက်သုံးမယ်။ Personal thread က သီးခြားရှိမယ်။ စာချုပ် link၊ ပေးပို့မှု link နှင့် event တို့မှာ တူညီသော participant စစ်ဆေးမှု ရှိမယ်။ လျှောက်လွှာမရှိ၊ အပ်နှံမထား၊ သို့မဟုတ် ခွင့်ပျက်ပါက ဘယ်အပိုင်းကြည့်နိုင်သေးကြောင်း ဆာဗာရလဒ်အတိုင်း ပြမယ်။
- **မျက်နှာပြင်**။ အလုပ်ခန်းမှာ အကျဉ်းချုပ်နှင့် လုပ်ဆောင်ရန်၊ ဆွေးနွေးမှု၊ ပေးပို့မှု၊ ပေးချေမှုအခြေအနေ၊ အဖြစ်အပျက်မှတ်တမ်း ထားမယ်။ Desktop ဘေးပြား၊ tablet တွင် ဖွင့်ပိတ်နိုင်သော panel၊ mobile တွင် လမ်းကြောင်းသီးခြား သို့မဟုတ် ပြန်သွားလို့ရသော tab ကို သုံးမယ်။ စာချုပ်နှင့် စကားပြောစာမျက်နှာက ဆက်စပ်မျက်နှာပြင်ဆီ အပြန်အလှန် သွားနိုင်မယ်။
- **ပို့ဆောင်မှု**။ ဆက်သွယ်မှုပြတ်လျှင် စာကြမ်း ထိန်းထားပြီး ပြန်ကြိုးစားနိုင်မယ်။ ဆာဗာအတည်ပြုချက်နှင့် ဖတ်ပြီးကြောင်း သီးခြားပြမယ်။ ပေးပို့မှုတူကို retry လုပ်ခြင်း၊ realtime ပြန်ချိတ်ခြင်းနှင့် သမိုင်းအပိုင်းလိုက်တင်ခြင်းက စာမထပ်၊ အစဉ်မပြောင်း၊ scroll နေရာမပျောက်ရ။ စာရှာဖွေမှုနှင့် ဖိုင်ပူးတွဲမှုကို နောက်အဆင့်မှာ ထည့်မယ်။
- **အလုပ်ပေးပို့မှု**။ ဖိုင်ပူးတွဲမှုအတွက် ခွင့်ရှိသူသာ ဖတ်နိုင်သည့် storage၊ ဖိုင်စစ်ဆေးခြင်း၊ သက်တမ်းတို download URL၊ အရွယ်အစား/အမျိုးအစားကန့်သတ်မှုနှင့် လက်ခံပြီးဗားရှင်းကို ထိန်းသိမ်းမှု လိုတယ်။ ပြန်ပြင်ရန် တောင်းသောအခါ ဗားရှင်းဟောင်းကို အစားမထိုးဘဲ timestamp နှင့် မှတ်ချက်ထားမယ်။
- **မဖြစ်မနေခွဲထားရမည့် အခြေအနေ**။ အလုပ်လက်ခံပြီး၊ ပေးချေမှုပြုလုပ်ရန် အသင့်၊ provider ရှင်းလင်းပြီးနှင့် ငွေထုတ်ယူပြီးတို့ကို သီးခြားပြမယ်။ Client၊ Freelancer၊ Admin၊ Support တို့၏ အရေးယူခွင့်ကို state transition တိုင်းမှာ စစ်မယ်။ ပြင်ဆင်ထားသော UI စာသားဖြင့် provider status မပြောင်းရ။

## ၅။ ပရိုဖိုင်၊ လူမှုကွန်ရက်၊ အစီအစဉ်နှင့် ဆက်တင်

- **ပရိုဖိုင်နှင့် လက်ရာ**။ Freelancer အတွက် လုပ်နိုင်စွမ်း၊ လက်ရာကဏ္ဍ၊ ရရှိသော review နှင့် ဆက်သွယ်ရန် လုပ်ဆောင်ချက်။ Client အတွက် လုပ်ငန်းအကျဉ်း၊ ဖွင့်ထားသောအလုပ်နှင့် review။ ပိုင်ရှင်အတွက် ပြင်ဆင်မှု၊ အခြားအဖွဲ့ဝင်မြင်ရမည့် ပုံစံ preview နှင့် ပုံများ မည်သူမြင်မည်ကို တင်မီပြမယ်။ လက်ရာအတွက် title၊ အကြောင်းအရာ၊ ကိုယ်တာဝန်၊ ရလဒ်၊ ပုံ/လင့်ခ်နှင့် ပြသအစီအစဉ်ကို သတ်မှတ်နိုင်မယ်။ Private အလုပ်နမူနာ အသစ်များအတွက် ခွင့်ပြုချက်နှင့် ပုံအသုံးပြုခွင့်ကို သီးခြားစစ်မယ်။
- **ပညာရှင်ကွန်ရက်**။ ပို့စ်၊ ဝန်ဆောင်မှုနမူနာနှင့် ချိတ်ဆက်မှုအပေါ် အခြေခံမယ်။ တုံ့ပြန်ချက်၊ မှတ်ချက်နှင့် မျှဝေရာတွင် ရင်းမြစ်/မြင်နိုင်မှုကို ပြမယ်။ ချိတ်ဆက်လက်ခံမှ personal chat ဖွင့်နိုင်မယ်။ Block၊ mute နှင့် report တို့၏ အကျိုးသက်ရောက်မှုကို ရှင်းပြပြီး အလုပ်သမိုင်းကို ထိန်းမယ်။ Post audience နှင့် စီစဉ်ပြသမှုကို နောက်အဆင့်မှာ အတည်ပြုမယ်။
- **အဖွဲ့ဝင်အစီအစဉ်**။ Free၊ Plus၊ Gold နှင့် Premium ကို role အလိုက် နှိုင်းနိုင်မယ်။ အသုံးပြုပြီးသော quota၊ နောက်သက်တမ်း၊ ပြောင်းလဲမည့်အကျိုးခံစားခွင့်၊ ပိတ်ထားသော sandbox နှင့် အစီအစဉ်သက်တမ်းကုန်မှုကို ဆာဗာဒေတာအတိုင်း ပြမယ်။ လက်ရှိ `membership_plans` နှင့် `membership_entitlements` သည် အားကိုးရမည့်ရင်းမြစ်။ `membership_tiers` စီမံမျက်နှာပြင်နှင့် စာရင်းတူကြောင်း မယူဆရ။ KAV နှုန်း၊ အခနှင့် တိုးမြှင့်မှုတို့မှာ စမ်းသပ်တန်ဖိုးဟု မြင်သာစေမယ်။ [အဖွဲ့ဝင် quota ကန့်သတ်မှု](../supabase/migrations/202611150017_harden_membership_quota_and_sandbox_pause.sql)
- **အကောင့်ဆက်တင်**။ အကောင့်အချက်အလက်၊ ပရိုဖိုင်/မြင်နိုင်မှု၊ စကားဝှက်နှင့် session၊ သတိပေးချက်၊ ဘာသာစကား/အချိန်ဇုန်၊ အလင်း/အမှောင်၊ အဖွဲ့ဝင်အစီအစဉ်၊ ကူညီရေး၊ ကိုယ့်ဒေတာတောင်းယူခြင်းနှင့် အကောင့်ပိတ်ခြင်းကို ရှာတွေ့နိုင်အောင် အုပ်စုခွဲမယ်။ ပိုမိုအရေးကြီးသည့် ပြောင်းလဲမှုများတွင် ပြန်အတည်ပြုမှု၊ အကျိုးသက်ရောက်မည့်အချိန်နှင့် ပြန်လည်ရယူနည်း ပါမယ်။ အကောင့်ပိတ်မှုတွင် စာချုပ်၊ audit နှင့် ငွေစာရင်း ထိန်းသိမ်းရန် စည်းမျဉ်းရှင်းပြီးမှ စတင်မယ်။

| စောင့်ကြည့်ထိန်းသိမ်းမှု | Report ကို လက်ခံပြီး ရည်ညွှန်းအမှတ်၊ အခြေအနေ၊ နောက်ထပ်အချက်အလက် တောင်းနိုင်သည့် လမ်းကြောင်း ပေးမယ်။ အမှုစီသူက သက်သေကို သက်ဆိုင်ရာခွင့်ဖြင့်သာ ကြည့်နိုင်မယ်။ ဆုံးဖြတ်ချက်၊ အကြောင်းရင်း၊ ပြန်လည်တင်ပြနိုင်မှုနှင့် တာဝန်ပြောင်းလွှဲမှုကို audit မှတ်မယ်။ |
| အငြင်းပွားမှု | အကြောင်းရင်း၊ သက်သေ၊ တင်သွင်းရမည့်အချိန်၊ စုံစမ်းဆဲ အခြေအနေနှင့် ဆုံးဖြတ်ချက် ပြမယ်။ စုံစမ်းဆဲလုပ်ငန်းနှင့် payout ကို ခွဲပြမယ်။ Support က အမှုကို တင်ပြနိုင်ပြီး ငွေကြေးဆုံးဖြတ်ချက်မှာ သတ်မှတ်ထားသော တာဝန်ရှိသူနှင့် provider လုပ်ငန်းစဉ် လိုတယ်။ |
| တကယ့်ပေးချေမှုအတွက် သတ်မှတ်ချက် | လုပ်ငန်းဆောင်ရွက်မည့်နိုင်ငံနှင့် ငွေကြေးအလိုက် လိုင်စင်ရ provider၊ အတည်ပြုထားသည့် စာချုပ်နှင့် သုံးစွဲသူစိစစ်မှုတာဝန် ခွဲရမယ်။ Provider-hosted စာမျက်နှာ၊ အတည်ပြုထားသော server event၊ duplicate/replay ကာကွယ်မှု၊ စာရင်းတိုက်စစ်မှု၊ ပြန်အမ်းမှု၊ chargeback၊ pause နှင့် incident အစီအစဉ် လိုတယ်။ လွှဲပြောင်းပြီးမှုကို provider အတည်ပြုချက်ကို အခြေခံမယ်။ လက်ရှိ sandbox ledger ကို သီးခြား ထိန်းရမယ်။ |

## ၇။ အရည်အသွေးနှင့် ဖြန့်ချိမှု

- **လက်လှမ်းမီမှု**။ WCAG 2.2 AA ကို ရည်မှန်းချက်ထားမယ်။ အဓိကခရီးစဉ်ကို keyboard တစ်မျိုးတည်းနှင့် ပြီးစီးနိုင်ရမယ်။ Screen reader က လမ်းကြောင်း၊ ဖောင်အမှား၊ ရလဒ်အရေအတွက်နှင့် အခြေအနေပြောင်းလဲမှုကို သိနိုင်ရမယ်။ 320 CSS px၊ 200% zoom၊ အလင်း/အမှောင်နှစ်မျိုး၊ reduced motion နှင့် mobile keyboard တို့ကို ထုတ်လွှင့်မီ စစ်မယ်။ [W3C WCAG 2.2](https://www.w3.org/TR/WCAG22/)
- **ဒေသသုံးဘာသာ**။ ပထမ ဘာသာစကားနှစ်မျိုးကို English နှင့် မြန်မာအဖြစ် အဆိုပြုတယ်။ UI စာသား၊ error နှင့် notification တို့ကို message catalog ထဲစုမယ်။ `lang`၊ plural၊ ရက်စွဲ/အချိန်ဇုန်၊ ဂဏန်းနှင့် ငွေကြေး unit ကို locale အတိုင်း ပြမယ်။ စာချုပ်နောက်ဆုံးရက်မှာ အချိန်ဇုန်မြင်ရမယ်။ အသုံးပြုသူရေးသားသည့်စာကို မူရင်းအတိုင်း ထိန်းမယ်။
- **စမ်းသပ်မှုနှင့် တိုင်းတာမှု**။ ပင်မလုပ်ဆောင်ချက်တစ်ခုချင်းစီအတွက် success၊ မပြီးနိုင်သောအခြေအနေ၊ stale data နှင့် unauthorized အခြေအနေ ရှိရမယ်။ အစုလိုက်ဖတ်မှုအတွက် တည်ငြိမ်သော cursor၊ သုံးစွဲသူလုပ်အားထိခိုက်သည့် error/retry နှင့် ဖြန့်ချိမှုမတိုင်မီ စောင့်ကြည့်ချက်သတ်မှတ်မယ်။ [ဒီဇိုင်းစနစ်](techkarvo-design-system.md) · [အကောင်အထည်ဖော်အစီအစဉ်](techkarvo-implementation-roadmap.md)
