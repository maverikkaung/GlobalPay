# TechKarvo 4.4B — ပရိုဖိုင်နှင့် အဖွဲ့ဝင်အချက်အလက် ဖတ်ရှုခွင့်

ဤစာတမ်းသည် repository ရှိ migration 000–018 နှင့် React လုပ်ငန်းစဉ်များကို စစ်ထားသည့် ရလဒ်ဖြစ်သည်။ အောက်ပါ matrix သည် migration 019 ကို သီးသန့် PostgreSQL တွင် ထည့်သွင်းပြီးနောက် အသုံးပြုမည့် စည်းမျဉ်းဖြစ်သည်။ Staging အတွက် 019 ကို အသုံးချရန် သီးခြားခွင့်ပြုချက် လိုအပ်သည်။

## တွေ့ရှိချက်

- **ဦးစားပေးမြင့်** — Migration 018 အထိ Client နှင့် Freelancer ပရိုဖိုင် view နှစ်ခု၊ review view၊ portfolio နှင့် connection ဖတ်ရှုမှုတွင် နှစ်ဖက် block စစ်ဆေးချက် မပါဝင်ပါ။ လက်ရှိ React ပရိုဖိုင်သည် အချက်အလက်မတောင်းမီ block စစ်သော်လည်း ဤ database လမ်းကြောင်းများတွင် ထိုစည်းမျဉ်း မသက်ရောက်ပါ။ အခြေခံ owner နှင့် participant စည်းမျဉ်းများက ဆက်အလုပ်လုပ်သည်။
- **ဦးစားပေးမြင့်** — Block မပြုလုပ်မီ ဆောင်ရွက်ဆဲအလုပ် ရှိမရှိ စစ်ပေးသည့် RPC ဟောင်းတွင် အဆိုပါအလုပ်၏ ပါဝင်သူ ဟုတ်မဟုတ် မစစ်ပါ။ 019 တွင် ပါဝင်သူသာ ထိုအခြေအနေကို ရရှိပြီး အလုပ်ဆောင်ရွက်ဆဲအတွဲကို block မလုပ်နိုင်သည့် စည်းမျဉ်း ဆက်လက်အလုပ်လုပ်သည်။
- **Storage ကန့်သတ်ချက်** — `techkarvo-marketplace` သည် အများဖတ်နိုင်သော bucket ဖြစ်သည်။ ပရိုဖိုင်၊ portfolio ကိုယ်စားပြုပုံ သို့မဟုတ် social ပုံအတွက် ရှိပြီးသား အများဖတ် URL နှင့် ပြင်ပ site တွင် တင်ထားသည့် ပုံကို member block ဖြင့် ပြန်ပိတ်၍ မရပါ။ အနာဂတ်တွင် ဝင်ခွင့်ကန့်သတ်ထားသည့် portfolio ဖိုင်လိုပါက private bucket နှင့် သီးသန့်ဖတ်ရှုခွင့်တို့ကို အဟောင်း URL များ၊ cache နှင့် ဖိုင်ထိန်းသိမ်းမှု အစီအစဉ်အပါအဝင် သီးခြားသုံးသပ်ရမည်။ [Supabase Storage ဝင်ခွင့်ပုံစံ](https://supabase.com/docs/guides/storage/buckets/fundamentals)
- ပရိုဖိုင် view များသည် ပြသမည့် ပရော်ဖက်ရှင်နယ် အချက်အလက်၊ မီဒီယာလမ်းကြောင်းနှင့် Freelancer boost ရှိမရှိကိုသာ ထုတ်ပေးသည်။ အီးမေးလ်၊ ဖုန်း၊ Auth metadata၊ ငွေပေးချေမှုနှင့် message စာသား သီးခြား column မပါပါ။ ကိုယ်တိုင်ရေးသော bio၊ review နှင့် ပြင်ပ link တို့ထဲတွင် အသုံးပြုသူ ထည့်သည့် အချက်အလက်များကို ဤ read boundary က အလိုအလျောက် မဖယ်ရှားပေးပါ။
- အခြေခံ `profiles` row ကို ပိုင်ရှင်ကသာ ဖတ်/ပြင်နိုင်သည်။ Proposal တွင် သိမ်းထားသည့် ဆက်သွယ်ရန်အချက်အလက်ကို သက်ဆိုင်ရာ Client နှင့် Freelancer အတွက် သတ်မှတ်ထားသော RLS က စီမံသည်။ `reviews` ၏ base table တွင် review ရေးသူက ၎င်း၏ `application_id` နှင့် `reviewer_id` ကိုသာ ဖတ်နိုင်သည်။ စကားဝိုင်းနှင့် contract delivery များတွင် participant စစ်ဆေးမှု သီးသန့်ရှိသည်။ Personal conversation ကို block က ပိတ်ပြီး အလုပ်နှင့်ပတ်သက်သော သက်ဆိုင်သူမှတ်တမ်းများသည် သက်ဆိုင်ရာ စာချုပ်စည်းမျဉ်းအတိုင်း ဆက်ရှိသည်။ Ledger အခြေခံစာရင်းများအတွက် browser role များတွင် ဖတ်ခွင့် မရှိပါ။

## မူကြမ်းနှင့် စစ်ဆေးမှု

- `202611150019_enforce_profile_visibility.sql` သည် လက်ရှိ projection column များနှင့် boost တွက်ချက်မှုကို ထိန်းထားပြီး view သုံးခုတွင် နှစ်ဖက် block စစ်သည်။ Portfolio နှင့် connections တွင် လက်ရှိ RLS အပေါ် သီးသန့်ကန့်သတ် read policies ထည့်သည်။ မူကြမ်းတွင် အချက်အလက် ရေးသားခြင်း၊ Storage bucket/policy ပြောင်းလဲခြင်းနှင့် ငွေစာရင်းပြောင်းလဲခြင်း မပါဝင်ပါ။
- Settings သည် ကိုယ်တိုင် block လုပ်ထားသူ၏ အမည်ကို authenticated RPC မှ ရယူသည်။ API မတင်ရသေးသည့် version အတွက်သာ ယခင် ဖတ်ခွင့်ရှိသော view များကို အသုံးပြုသည်။ ခွင့်မရှိသော error ရလျှင် ယေဘုယျ label နှင့် block ဖြုတ်ခွင့်ကို ပြသနိုင်သည်။ Connections သည် လိုအပ်သော column များကိုသာ တောင်းပြီး အတည်ပြုထားသော ပိုင်ရှင်ဖိုင်လမ်းကြောင်းဖြင့် avatar ပြသသည်။
- သီးသန့် SQL စမ်းသပ်မှုတွင် owner editing၊ Client ဖတ်ခွင့်၊ အပြင်လူ၊ anonymous၊ identity မရှိသော authenticated role၊ နှစ်ဖက် block၊ unblock၊ review နှင့် column/grant တို့ကို စစ်သည်။ Loopback PostgREST စမ်းသပ်မှုက ထို read boundaries ကို fixture accounts ဖြင့် API မှ စစ်သည်။ Browser စမ်းသပ်မှုက Settings label၊ migration မတင်မီ fallback နှင့် permission error တို့ကို စစ်သည်။
- Local ရလဒ်များမှာ unit ၉၆ ခု၊ သီးသန့် PostgreSQL suite ၁၃ ခု၊ PostgREST API ၇ ခုနှင့် Playwright ၄၀ ခု အောင်မြင်သည်။ လေးမျိုးလုံးတွင် ကျရှုံးမှုနှင့် ကျော်ထားမှု ၀ ဖြစ်သည်။ Lint နှင့် production build လည်း အောင်မြင်သည်။ Staging တွင် ဒေတာရေးသော စမ်းသပ်မှု မပြုလုပ်ခဲ့ပါ။
- Staging တွင် သီးခြားခွင့်ပြုချက်ရပြီးမှ authenticated project identity၊ migration history၊ grants၊ RLS၊ Storage policy နှင့် အရေးကြီးစာရင်းများ၏ read-only baseline ကို တိုက်စစ်ရမည်။ Dry run တွင် 019 တစ်ခုတည်း ဖြစ်ကြောင်း အတည်ပြု၍ အသုံးချပြီးနောက် projection၊ grants နှင့် QA identities ခွဲထားသည့် read-only စစ်ဆေးမှု ပြန်လုပ်ရမည်။
